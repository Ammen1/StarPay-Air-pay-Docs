STARPAY API DOCUMENTATION

StarPay Air Pay Integration Guide

Server-to-Server Integration Guide

For Air Pay's backend team. You call StarPay from your own server to find merchants, create bills and confirm payments. There is no mini app, WebView or StarPay screen to add.

Start with Step 1. If you already have your credentials, go to Step 2 and build the client once.

🔐 Authenticated and encrypted

HTTP Basic authentication on every call, and NaCl box encryption on every POST body.

🏪 Find merchants two ways

Look up one merchant by its 8-digit ID, or list the merchants closest to a location.

💳 A two-call payment

Create Bill gives you a bill number. Confirm Bill marks it paid after you collect the money.

🧾 Safe to retry

StarPay refuses repeated requests and double confirms, so a retry can't pay a bill twice.

How a payment works

  1. Find the merchant with Get Merchant Detail or Get Nearby Merchants.
  2. Call Create Bill. StarPay returns a bill number and the status UNPAID.
  3. Collect the customer's payment in Air Pay.
  4. Call Confirm Bill with the bill number, Air Pay's payment reference and the bill amount. The status changes to PAID.
  5. StarPay credits the merchant in the background. Air Pay has nothing more to do for this bill.

All bills are in ETB and are valid for 24 hours, so collect the payment and confirm the bill within that time. Only the partner that created a bill can confirm it.

Purpose: your side of the encryption. StarPay reads your public key from each request, so there is nothing to register.

Where to get it: generate one key pair for each environment.

⚠️ Warning: Keep the secret key on Air Pay's backend only, never in a mobile app, browser or source control.

🔐 Step 2: Encrypt every request

Every POST body is encrypted with NaCl box (X25519, XSalsa20 and Poly1305), so only StarPay can read it. Every response is plain JSON. Build this once, as one reusable client, and every later step is just "call this path with this data".

  1. Air Pay sends GET /bill/getpubkey with Basic authentication.
  2. StarPay returns its public key.
  3. Air Pay encrypts the request JSON and adds the nonce, pubkey and checksum.
  4. Air Pay sends a POST request to the API it is calling, with Basic authentication and the encrypted body.
  5. StarPay checks the credentials, decrypts the body and checks the checksum.
  6. StarPay returns a plain JSON response.

Air Pay needs steps 1 and 2 only when it does not hold StarPay's current public key. Steps 3 to 6 happen on every POST request.

2.1 Request body

Each POST request sends these four fields, and all of them are required.

FieldContents
payloadThe encrypted request JSON, in Base64
nonceBase64A random 24-byte nonce, in Base64. Use a new nonce for every request
pubkeyAir Pay's 32-byte public key, in Base64
checksumSHA-256 of the plain request JSON, in lowercase hex
{
  "payload": "<encrypted request JSON in Base64>",
  "nonceBase64": "<24-byte nonce in Base64>",
  "pubkey": "<Air Pay public key in Base64>",
  "checksum": "<SHA-256 of the plain JSON in hex>"
}

2.2 Encrypt a request

  1. Convert the request fields to a JSON string.
  2. Calculate checksum from that exact string.
  3. Generate a new 24-byte nonce.
  4. Encrypt the string with the nonce, StarPay's public key and Air Pay's secret key.
  5. Send the four fields as JSON.
❗ Important: The most common mistake is calculating the checksum from a different string than the one you encrypt, for example after converting the JSON a second time. Convert it once, then use those exact bytes for both.

2.4 Put it together: one client

Each example is a complete client. It fetches and caches StarPay's public key, encrypts the request, calls the API, and retries once after a key change. Every later step calls this same client.

Set these environment variables on your server: STARPAY_BASE_URL, STARPAY_USERNAME, STARPAY_PASSWORD and AIRPAY_SECRET_KEY.

Node.js

Needs Node.js 18 or newer. Install with npm install tweetnacl tweetnacl-util.

const crypto = require("crypto");
const nacl = require("tweetnacl");
const naclUtil = require("tweetnacl-util");

const { STARPAY_BASE_URL, STARPAY_USERNAME, STARPAY_PASSWORD, AIRPAY_SECRET_KEY } = process.env;

const airPayKeys = nacl.box.keyPair.fromSecretKey(naclUtil.decodeBase64(AIRPAY_SECRET_KEY));
const credentials = Buffer.from(`${STARPAY_USERNAME}:${STARPAY_PASSWORD}`).toString("base64");
const authHeader = `Basic ${credentials}`;
let starpayPublicKey = null;

async function getStarPayPublicKey() {
  const response = await fetch(`${STARPAY_BASE_URL}/bill/getpubkey`, {
    headers: { Authorization: authHeader },
  });
  if (!response.ok) throw new Error(`Public key request failed: ${response.status}`);
  return (await response.json()).pubkey;
}

function encryptRequest(data, publicKeyBase64) {
  const message = JSON.stringify(data);
  const nonce = nacl.randomBytes(nacl.box.nonceLength);
  const encrypted = nacl.box(
    naclUtil.decodeUTF8(message),
    nonce,
    naclUtil.decodeBase64(publicKeyBase64),
    airPayKeys.secretKey,
  );
  return {
    payload: naclUtil.encodeBase64(encrypted),
    nonceBase64: naclUtil.encodeBase64(nonce),
    pubkey: naclUtil.encodeBase64(airPayKeys.publicKey),
    checksum: crypto.createHash("sha256").update(message).digest("hex"),
  };
}

// Every call makes a new nonce, so a retry is always a new encrypted request.
async function callStarPay(path, data, isRetry = false) {
  if (!starpayPublicKey) starpayPublicKey = await getStarPayPublicKey();

  const response = await fetch(`${STARPAY_BASE_URL}${path}`, {
    method: "POST",
    headers: { Authorization: authHeader, "Content-Type": "application/json" },
    body: JSON.stringify(encryptRequest(data, starpayPublicKey)),
  });
  const result = await response.json();

  // StarPay changes its key about every 15 days: fetch it again and retry once.
  if (!isRetry && String(result.ResultDesc).startsWith("Decryption failed")) {
    starpayPublicKey = null;
    return callStarPay(path, data, true);
  }
  return { status: response.status, result };
}

module.exports = { callStarPay, encryptRequest };

Call it like this:

const { callStarPay } = require("./starpay-client");

const { status, result } = await callStarPay("/bill/merchant-detail", {
  merchantId: "12345678",
});

Python

Install with pip install pynacl.

import base64
import hashlib
import json
import os
import urllib.error
import urllib.request

import nacl.public
import nacl.utils

BASE_URL = os.environ["STARPAY_BASE_URL"]
credentials = f'{os.environ["STARPAY_USERNAME"]}:{os.environ["STARPAY_PASSWORD"]}'
AUTH_HEADER = "Basic " + base64.b64encode(credentials.encode()).decode()
AIRPAY_KEY = nacl.public.PrivateKey(base64.b64decode(os.environ["AIRPAY_SECRET_KEY"]))
starpay_public_key = None


def send(request):
    try:
        with urllib.request.urlopen(request, timeout=30) as response:
            return response.status, json.load(response)
    except urllib.error.HTTPError as error:
        return error.code, json.load(error)


def get_starpay_public_key():
    request = urllib.request.Request(
        f"{BASE_URL}/bill/getpubkey", headers={"Authorization": AUTH_HEADER}
    )
    status, body = send(request)
    if status != 200:
        raise RuntimeError(f"Public key request failed: {status}")
    return body["pubkey"]


def encrypt_request(data, public_key_base64):
    message = json.dumps(data, separators=(",", ":")).encode()
    nonce = nacl.utils.random(nacl.public.Box.NONCE_SIZE)
    public_key = nacl.public.PublicKey(base64.b64decode(public_key_base64))
    box = nacl.public.Box(AIRPAY_KEY, public_key)
    return {
        "payload": base64.b64encode(box.encrypt(message, nonce).ciphertext).decode(),
        "nonceBase64": base64.b64encode(nonce).decode(),
        "pubkey": base64.b64encode(bytes(AIRPAY_KEY.public_key)).decode(),
        "checksum": hashlib.sha256(message).hexdigest(),
    }


# Every call makes a new nonce, so a retry is always a new encrypted request.
def call_starpay(path, data, is_retry=False):
    global starpay_public_key
    if starpay_public_key is None:
        starpay_public_key = get_starpay_public_key()

    request = urllib.request.Request(
        f"{BASE_URL}{path}",
        data=json.dumps(encrypt_request(data, starpay_public_key)).encode(),
        headers={"Authorization": AUTH_HEADER, "Content-Type": "application/json"},
        method="POST",
    )
    status, result = send(request)

    # StarPay changes its key about every 15 days: fetch it again and retry once.
    if not is_retry and str(result.get("ResultDesc", "")).startswith("Decryption failed"):
        starpay_public_key = None
        return call_starpay(path, data, True)
    return status, result

Call it like this:

from starpay_client import call_starpay

status, result = call_starpay("/bill/merchant-detail", {"merchantId": "12345678"})

Any other NaCl-compatible library works too, such as libsodium's crypto_box_easy.

2.5 Retries

  • Key change: after Decryption failed, fetch the public key again, encrypt again and retry once.
  • Timeout: encrypt the request again with a new nonce before you retry. Create Bill and Confirm Bill refuse an encrypted request they have already received.
  • Server errors: treat every 5xx response as temporary and retry later.

3.3 Results to expect

  • Empty list: when no merchant is found, the response is a success with an empty merchantData list.
  • Fewer than 50: StarPay takes the 50 closest merchants first, then removes those that are disabled or not at Level 3.
  • Saved location needed: only merchants with a saved location appear. Get Merchant Detail can still find a merchant that is missing here.
  • Coordinates: send latitude and longitude as JSON numbers. A value of 0 counts as missing.

5.4 After a timeout

Encrypt the same values again with a new nonce and retry. Do not charge the customer again. If the reply is Transaction is not unpaid, the first call may have succeeded, so check with StarPay.

🚀 Step 7: Go live

Air Pay starts in the Test environment and moves to Production after StarPay signs off the integration.

  1. Get the Test base URL, username and password from StarPay (Step 1).
  2. Generate an X25519 key pair for Test and build the client (Step 2).
  3. Call Get Merchant Detail with a test merchant ID, then Get Nearby Merchants with a test location (Step 3).
  4. Create a bill, make a test payment, then confirm the bill (Step 4 and Step 5).
  5. Handle every response in Step 6, including the retry after a key change.
  6. Complete the checklist below and send StarPay your test results for sign-off.
  7. Repeat Step 1 and Step 2 with the Production base URL and credentials.

Go-live checklist

Credentials (Step 1)

  • ☐  The username, password and secret key are only on Air Pay's backend
  • ☐  Test and Production use separate credentials and key pairs

Every request (Step 2)

  • ☐  Every request uses a new random nonce
  • ☐  The checksum is calculated from the exact string that is encrypted
  • ☐  Your code matches the worked example in 2.3
  • ☐  After Decryption failed, the backend fetches the public key again and retries once

Merchant lookup (Step 3)

  • ☐  The app handles an empty merchant list, a missing logo and Merchant not found.
  • ☐  Merchant names are formatted for display

Payment flow (Step 4 and Step 5)

  • ☐  Confirm Bill is called only after the customer's payment has succeeded
  • ☐  The backend does not charge a customer for an expired bill
  • ☐  Confirm Bill is sent once per payment, with a reference unique to that payment
  • ☐  A timed-out request is encrypted again with a new nonce before it is retried, without charging the customer again
  • ☐  All four APIs have passed testing in the Test environment

Secrets hygiene

  • ☐  Logs do not contain credentials, secret keys or customer locations
